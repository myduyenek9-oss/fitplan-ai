# Task 7 前端杂志风 UI 外壳与视觉系统设计

- 日期：2026-07-21
- 状态：已获得用户方向确认，待用户审阅书面规格
- 范围：Task 7，仅实现前端响应式外壳、视觉系统和基础通用组件；不实现完整业务页面和复杂数据流

## 1. 背景

当前项目已经完成后端的热量计算、记录、计划、AI 自然语言记录和 AI 对话调整能力。前端目前只有最小的 `FitPlan AI` 标题页。

用户已确认首页方向采用 **“博客 App 风格首页 + AI 教练入口”**：整体要有生活方式、健康杂志、卡片阅读感，同时保留清晰的热量记录和计划调整入口。

## 2. 本阶段目标

Task 7 的目标是建立前端后续开发可复用的 UI 基础：

1. 定义暖白、深绿、暖橙的视觉令牌。
2. 建立响应式应用外壳：手机底部导航，桌面左侧导航。
3. 提供可复用的卡片和按钮组件。
4. 把首页临时替换为杂志风的静态示例布局，为后续 Task 8 接真实业务页面做准备。
5. 建立前端 API 和类型文件骨架，避免后续页面重复定义接口。

本阶段不接入真实后端接口，不实现登录、完整表单、图表和 AI 对话业务逻辑。

## 3. 视觉方向

### 3.1 关键词

- 暖白背景
- 深绿色主色
- 暖橙色强调
- 杂志 / 博客 App 风格
- 大圆角卡片
- 胶囊按钮
- 充足留白
- 亲和但专业

### 3.2 色彩

建议 CSS 变量：

- `--color-bg`: 暖米白页面背景
- `--color-surface`: 主卡片白色或浅奶白
- `--color-surface-muted`: 柔和浅绿或浅橙背景块
- `--color-primary`: 深绿色，用于主要按钮、导航选中态和重点数据
- `--color-primary-soft`: 浅绿色，用于轻提示背景
- `--color-accent`: 暖橙色，用于行动按钮、进度强调和少量标签
- `--color-text`: 深灰绿色文本
- `--color-muted`: 次级文字
- `--color-border`: 柔和边框

色彩使用原则：

- 页面大面积使用暖白，不使用纯白冷感背景。
- 深绿色用于稳定感和健康感。
- 暖橙只做少量重点，不大面积铺满。
- 数据卡片可以使用浅绿、浅橙、米色等低饱和底色区分。

### 3.3 字体与排版

- 中文界面优先使用系统字体栈，保证阿里云部署和不同设备显示稳定。
- 标题使用更大的字号和稍紧凑字重，制造杂志标题感。
- 正文保持清晰，不追求过度装饰。
- 关键数字例如 `1850 kcal`、`剩余 420` 使用大号数字样式。

## 4. 响应式布局

### 4.1 手机端

手机端采用卡片流：

1. 顶部欢迎区：
   - 产品名或问候语；
   - 当前目标，例如“减脂 · 第 2 周”；
   - 简短 AI 建议。
2. 今日计划大卡片：
   - 推荐摄入、已摄入、剩余热量；
   - 今日运动目标；
   - 一个醒目的胶囊主按钮。
3. 快捷操作按钮组：
   - 记录饮食；
   - 记录运动；
   - 和 AI 调整计划。
4. 今日记录区：
   - 显示最近饮食 / 运动记录摘要。
5. AI 建议卡片：
   - 展示一句可行动的建议。
6. 底部导航：
   - 首页；
   - 记录；
   - 计划；
   - AI 教练；
   - 我的。

手机端导航固定在底部，内容区域底部要预留安全距离，避免被导航挡住。

### 4.2 桌面端

桌面端采用左侧导航 + 主内容杂志式仪表盘：

- 左侧为品牌、导航、目标摘要。
- 主区域居中限制最大宽度，避免内容过宽。
- 首页使用两列布局：
  - 左侧为今日计划、记录、AI 建议；
  - 右侧为热量指标卡和计划摘要。

桌面端不显示底部导航。

## 5. 通用组件设计

### 5.1 `AppShell`

职责：

- 提供整体页面结构。
- 根据屏幕宽度展示 `SidebarNav` 或 `BottomNav`。
- 提供统一 header 区域和 main 内容区。
- 接收当前导航项、页面标题、页面副标题和 children。

非职责：

- 不负责业务数据请求。
- 不负责认证状态判断。
- 不持有复杂页面状态。

### 5.2 `SidebarNav`

职责：

- 桌面导航。
- 展示品牌名 `FitPlan AI`。
- 展示导航列表。
- 显示一个简短目标摘要卡，例如“本周目标：稳定减脂”。

### 5.3 `BottomNav`

职责：

- 手机端底部导航。
- 使用清晰文字和简单符号或 emoji 风格图标。
- 当前页面有深绿色选中态。

### 5.4 `EditorialButton`

按钮风格：胶囊形、轻阴影、明确状态。

支持属性：

- `variant`: `primary` | `accent` | `secondary`
- `loading`: 加载态
- `disabled`: 禁用态
- `icon`: 可选图标
- 原生 button 属性，例如 `type`、`onClick`、`aria-label`

按钮文案示例：

- 记录饮食
- 记录运动
- 和 AI 调整计划
- 保存计划

测试要求：

- 渲染 primary 和 secondary 样式。
- 可通过可访问名称找到按钮。
- disabled 时不可点击。
- loading 时显示加载文案并禁用。

### 5.5 `MetricCard`

职责：

- 展示一个关键指标。
- 支持标题、数值、单位、说明、趋势/状态。

示例：

- 今日目标：1850 kcal
- 已摄入：1280 kcal
- 剩余：570 kcal
- 运动消耗：320 kcal

### 5.6 `SectionCard`

职责：

- 作为页面内容区块容器。
- 支持标题、副标题、右侧操作区域和 children。
- 用于今日记录、AI 建议、计划摘要等区域。

## 11. 风险与处理

### 风险 1：视觉做得太重，影响后续业务扩展

处理：组件只负责布局和样式，不把静态示例写死到组件内部。

### 风险 2：移动端底部导航遮挡内容

处理：全局布局为 main 内容增加底部 padding，并使用安全区域变量。

### 风险 3：按钮样式好看但可访问性差

处理：按钮保留原生 button 语义，测试可访问名称、禁用态和加载态。

### 风险 4：类型过早设计过复杂

处理：类型只覆盖当前 shell 和示例页面所需字段，后续按页面扩展。
