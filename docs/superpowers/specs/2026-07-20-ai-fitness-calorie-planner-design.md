# AI 健身热量与计划管理平台设计

- 日期：2026-07-20
- 状态：设计已获得用户确认，待用户审阅书面规格
- 范围：个人自用 MVP

## 1. 产品目标

构建一个手机和电脑都可使用的响应式网页，帮助个人根据身体资料和健身目标计算热量、生成饮食和运动计划，并通过自然语言持续记录每日饮食和运动。

系统需要让用户可以直接说“我刚吃了一个汉堡和一杯奶茶”，自动估算热量、写入当天记录、更新剩余热量、给出晚餐或运动建议，并通过钉钉群机器人推送反馈。

第一版支持：

- 减脂、增肌、维持体重三类目标；
- BMR、TDEE、每日热量和三大营养素目标计算；
- AI 生成 7 天饮食和运动计划；
- 自然语言记录饮食和运动；
- 记录体重、体脂率和身体围度；
- 计划保存、对话修改、记录撤销/编辑/删除；
- 每日计划推送和记录后的钉钉反馈推送；
- 阿里云 Docker 部署。

## 2. 非目标

第一版不包含：

- 多用户社交、好友和排行榜；
- 原生 iOS/Android App；
- 食物拍照识别；
- 智能手环实时同步；
- 在线商城、订阅和支付；
- 营养师/教练后台；
- 复杂的食物数据库后台管理。

## 3. 用户与使用场景

第一版面向单个个人用户。认证采用单用户登录和会话机制，不做复杂的组织、角色和权限系统。

核心使用场景：

1. 用户填写身体资料、活动量、目标、运动条件和饮食偏好。
2. 系统计算热量和营养目标。
3. AI 根据目标生成 7 天计划。
4. 用户每天查看今日计划。
5. 用户用自然语言记录饮食或运动。
6. 系统自动更新当天数据并给出调整建议。
7. 系统按配置向钉钉发送每日计划和记录反馈。
8. 用户查看历史记录和身体趋势。

## 4. 信息架构与页面

### 4.1 今日首页

首页是最高频页面，展示：

- 今日热量目标、已摄入、剩余热量；
- 蛋白质、碳水、脂肪完成度；
- 今日训练和完成状态；
- 最近体重/体脂率变化；
- 最近饮食和运动记录；
- 常驻 AI 输入框；
- 钉钉推送状态。

首页主操作：

- “记录饮食”；
- “记录运动”；
- “和 AI 调整计划”。

### 4.2 首次设置

使用分步表单收集：

- 年龄、性别、身高、体重；
- 体脂率和身体围度，可选；
- 活动量；
- 减脂、增肌或维持体重；
- 目标体重或目标体脂率，可选；
- 每周可运动天数；
- 家里、健身房或户外；
- 饮食偏好和忌口；
- 用餐习惯和每日作息。

完成后生成初始热量目标和 7 天计划。

### 4.3 AI 计划与对话

用户可以查看、解释和修改计划。支持自然语言指令：

- “周三没时间去健身房”；
- “我不吃鸡胸肉”；
- “把训练强度降低”；
- “早餐改成方便带走的食物”；
- “刚吃了一个汉堡和一杯奶茶”。

涉及饮食或运动记录的消息会进入结构化记录流程；涉及计划调整的消息会生成计划版本或更新当天建议。

### 4.4 记录

按日期展示饮食、运动、身体数据和 AI 调整记录。每条 AI 自动记录支持编辑、删除和撤销。

### 4.5 趋势

展示体重、体脂率、围度、每日热量摄入和运动完成度的周/月趋势。

### 4.6 设置

包含个人资料、目标、饮食偏好、AI 中转 API、钉钉 Webhook、推送时间、数据导出和重新生成计划。

## 5. UI 视觉规范

视觉方向参考用户提供的“博客类 App 设计灵感”页面中的内容阅读和卡片排版感觉，但不直接复制参考图片或素材：

- 页面背景：米白或浅灰；
- 主色：深绿；
- 强调色：暖橙、浅绿；
- 内容容器：大圆角卡片、柔和阴影、充足留白；
- 手机端：卡片流和底部导航；
- 电脑端：杂志式仪表盘和左侧导航；
- 主要信息：大标题、大数字、短句建议；
- 主按钮：Editorial Capsule 胶囊按钮，采用图标 + 动作型文字 + 深绿/橙色底；
- 次按钮：透明或米白底、细边框胶囊按钮；
- 主操作文案使用“记录饮食”“和 AI 调整计划”等动词，不使用“提交”“确定”等后台术语。

参考页面：`https://www.shejidaren.com/ui-ux-anli.html`。

## 6. 计算规则

热量计算由后端确定性模块完成，AI 不负责直接决定基础热量结果。

推荐计算流程：

1. 使用 Mifflin-St Jeor 公式计算 BMR；
2. 根据活动量乘以活动系数得到 TDEE；
3. 根据目标类型计算每日热量目标；
4. 根据目标和体重计算蛋白质目标；
5. 用剩余热量分配碳水和脂肪；
6. 对过低热量目标、极端减重速度和异常资料给出安全提示。

AI 负责自然语言理解、食物/运动解析、计划文本生成和调整建议。AI 估算结果必须标记为估算值，并允许用户修改。

## 7. AI 集成设计

AI 服务采用 OpenAI 兼容接口，通过后端配置：

```env
AI_BASE_URL=
AI_API_KEY=
AI_MODEL=
```

前端不能直接读取 API Key。

### 7.1 饮食记录解析

接口：`POST /api/records/food/natural-language`

请求：

```json
{
  "text": "刚才吃了一个鸡腿堡和一杯奶茶"
}
```

AI 内部要求返回结构化 JSON，至少包含：

- 食物名称；
- 估算分量；
- 估算热量；
- 蛋白质、碳水、脂肪；
- 估算置信度；
- 不确定项说明。

后端校验 JSON，写入 `food_logs`，重新计算当天累计数据，再生成调整建议。

### 7.2 运动记录解析

用户可以输入“跑步 30 分钟”“完成了今天的腿部训练”等内容，AI 解析运动类型、时长、强度和估算消耗，后端保存到 `exercise_logs`。

### 7.3 连续对话

对话记录保存到数据库。每次调用 AI 时，只传递必要的个人资料摘要、当前计划、当天记录和最近对话，避免无限增长上下文。

## 8. 数据模型

核心表：

- `profile`：个人资料；
- `goals`：目标和目标参数；
- `plans`：计划版本；
- `plan_days`：计划每日内容；
- `food_logs`：饮食记录；
- `exercise_logs`：运动记录；
- `body_metrics`：体重、体脂率和围度；
- `conversations`：AI 对话；
- `notification_logs`：钉钉推送日志；
- `settings`：AI、钉钉和推送设置。

计划采用版本概念。用户修改计划时生成新版本或更新当前计划，并保留调整原因，避免历史记录被静默覆盖。

## 9. 后端架构

使用 React + TypeScript 前端、FastAPI 后端、PostgreSQL 数据库和 Docker Compose。

FastAPI 模块：

```text
app/
├── auth/
├── profile/
├── calorie/
├── plans/
├── records/
├── ai/
├── notifications/
├── scheduler/
└── settings/
```

主要 API：

```text
POST /api/profile
GET  /api/dashboard
POST /api/plans/generate
GET  /api/plans/current
POST /api/records/food/natural-language
POST /api/records/exercise
POST /api/records/body-metrics
GET  /api/records/daily
GET  /api/trends
POST /api/ai/chat
POST /api/notifications/test-dingtalk
PUT  /api/settings
```

## 10. 钉钉推送

第一版使用钉钉群机器人 Webhook + 加签。

### 10.1 每日推送

由定时任务在用户配置的时间发送：

- 今日热量目标；
- 饮食计划；
- 运动安排；
- 注意事项；
- 连续完成情况。

### 10.2 记录后反馈

新增饮食或运动记录后，重新计算当天数据，并按推送设置发送：

- 本次估算热量；
- 当天已摄入和剩余热量；
- 营养素完成度；
- 晚餐或运动调整建议。

支持“每次推送、超标时推送、合并推送、关闭即时推送”四种策略。

所有发送结果写入 `notification_logs`，失败时记录错误并进行有限次数重试。

## 11. 阿里云部署

第一版部署到一台阿里云 ECS 或轻量应用服务器，使用 Docker Compose：

```text
Nginx/Caddy
├── React 静态文件容器
├── FastAPI 容器
├── 定时任务容器
└── PostgreSQL 容器
```

敏感配置通过环境变量注入，不提交到代码仓库。生产环境启用 HTTPS、健康检查、日志脱敏、API 限流和 PostgreSQL 定时备份。

备份至少保留最近 7～30 天，并支持用户导出 JSON 数据。

## 12. 安全与健康边界

- AI 仅提供健身和饮食建议，不作为医疗诊断；
- 对疾病、孕期、严重不适和极端目标给出咨询专业人士提示；
- 不鼓励极端节食；
- 对过低热量目标和异常减重速度提示风险；
- AI 估算食物热量明确标注为估算值；
- 所有自动记录支持编辑、删除和撤销；
- API Key、钉钉密钥和数据库密码只存在服务端环境变量。

## 13. MVP 验收标准

完整跑通以下流程即视为 MVP 主流程完成：

```text
填写个人资料
→ 计算 BMR/TDEE 和目标热量
→ AI 生成 7 天计划
→ 查看今日计划
→ 自然语言记录饮食
→ 自动更新当天热量
→ 生成晚餐/运动调整建议
→ 保存记录和对话
→ 钉钉发送反馈
→ 查看体重、体脂率、围度趋势
```

额外验收要求：

- 手机和电脑布局可用；
- AI 服务不可用时，页面显示可理解的错误，不丢失原始输入；
- 钉钉推送失败不影响饮食和运动记录保存；
- 自动估算记录可以编辑、删除和撤销；
- 数据库可备份和恢复；
- 生产配置中没有硬编码密钥。
